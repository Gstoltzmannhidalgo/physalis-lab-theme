02
Estructura de Rutas (App Router)
Ruta Propósito y Contenido
/Home editorial. Hero de colección activa + diseñadores destacados + últimas piezas.
/designersGalería de todos los diseñadores. Filtros por origen, estilo, especialidad.
/designers/[slug]Perfil completo del diseñador + biografía + catálogo de piezas disponibles.
/shopCatálogo general. Filtros por tipo (lámpara, macetero, etc.), material, precio, diseñador.
/shop/[slug]Ficha de producto: galería de fotos, historia, materiales, stock limitado visible, add-to-cart.
/cartCarrito. Resumen de items, subtotal, acceso a checkout.
/checkoutDatos de envío + integración Mercado Pago → redirect a pago seguro MP.
/orders/[id]Confirmación de pedido con número de seguimiento y estado actualizado.
/collections/[slug]Colecciones especiales / ediciones limitadas con contador de unidades.
/adminPanel de administración protegido. Gestión de productos, pedidos, diseñadores.
/api/mp/create-preferenceEndpoint POST: crea preferencia de pago en Mercado Pago. Retorna init_point.
/api/mp/webhookEndpoint POST: recibe notificaciones de MP (pago aprobado/rechazado). Actualiza BD.
03
Flujo de Pago con Mercado Pago (Checkout Pro)
1
Cliente
Llena carrito y confirma datos de envío en la web.
2
API Interna
POST a /api/mp/create-preference con items y total.
3
Mercado Pago
MP crea preferencia y retorna init_point (URL de pago).
4
Redirect
Cliente es redirigido a página segura de MP para pagar.
5
Webhook
MP notifica a /api/mp/webhook con resultado del pago.
6
Producción
BD actualizada. Email de confirmación enviado. Pedido entra a producción.
1
Crear cuenta Mercado Pago Chile
Ir a mercadopago.cl → Crear cuenta → Verificar identidad como empresa.
2
Obtener credenciales
Panel MP → Tus integraciones → Credenciales → Obtener ACCESS_TOKEN y PUBLIC_KEY (producción y sandbox).
3
Configurar en Vercel
Vercel Dashboard → Settings → Environment Variables → Agregar todas las variables de entorno listadas abajo.
4
Configurar webhook en MP
Panel MP → Notificaciones → URL: https://physalislab.cl/api/mp/webhook → Activar eventos de pago.
5
Instalar SDK en proyecto
npm install mercadopago → Importar y configurar con ACCESS_TOKEN en la ruta API.
// /app/api/mp/create-preference/route.ts import { MercadoPagoConfig, Preference } from 'mercadopago'; const client = new MercadoPagoConfig({ accessToken: process.env.MP_ACCESS_TOKEN!, }); export async function POST(req: Request) { const { items, payer } = await req.json(); const preference = new Preference(client); const result = await preference.create({ body: { items, // [{ title, quantity, unit_price, currency_id: 'CLP' }] payer, back_urls: { success: `${process.env.NEXT_PUBLIC_SITE_URL}/orders/success`, failure: `${process.env.NEXT_PUBLIC_SITE_URL}/checkout?error=1`, }, auto_return: 'approved', notification_url: `${process.env.NEXT_PUBLIC_SITE_URL}/api/mp/webhook`, } }); return Response.json({ init_point: result.init_point }); }
04
Pipeline GitHub → Vercel (CI/CD)
⎇
Configuración GitHub
1
Crear repositorio physalis-lab-web (privado) en GitHub.
2
Ramas: main = producción · dev = staging/testing.
3
Proteger rama main: requerir PR + review antes de merge.
4
Agregar .env.local al .gitignore. Nunca subir credenciales al repo.
▲
Configuración Vercel
1
Vercel → New Project → Import desde GitHub → Seleccionar repo.
2
Framework: Next.js (auto-detectado). Build command default.
3
Settings → Environment Variables → Agregar todas las variables.
4
Settings → Domains → Agregar physalislab.cl y configurar DNS.
↑
Flujo de Deploy
1
Desarrollas en rama feature/nueva-coleccion localmente.
2
Push a rama dev → Vercel genera automáticamente una Preview URL.
3
Revisas en Preview URL → si todo OK, merge a main.
4
Push a main → Vercel despliega a producción automáticamente en ~30 seg.

05
Variables de Entorno
⚠ Regla crítica: Nunca subir estas variables al repositorio GitHub. Configurarlas únicamente en el panel de Vercel (Settings → Environment Variables) y en tu archivo .env.local local (en .gitignore).
MP_ACCESS_TOKENToken de acceso Mercado Pago — producción. Obtenido en panel de desarrolladores MP.
MP_PUBLIC_KEYClave pública MP. Usada en el frontend para inicializar MP si se usa Checkout API.
MP_WEBHOOK_SECRETSecreto para verificar autenticidad de notificaciones del webhook de MP.
NEXT_PUBLIC_SITE_URLURL pública del sitio: https://physalislab.cl. Usada en back_urls de MP.
DATABASE_URLString de conexión a Supabase PostgreSQL. Obtenido en Settings → Database → Connection string.
SUPABASE_URLURL del proyecto Supabase. Formato: https://[id].supabase.co
SUPABASE_ANON_KEYClave anónima pública de Supabase. Para operaciones de cliente.
SUPABASE_SERVICE_KEYClave de servicio Supabase (solo backend/server). Nunca al cliente.
NEXTAUTH_SECRETSecreto aleatorio para NextAuth. Generado con: openssl rand -base64 32
RESEND_API_KEYAPI Key de Resend para envío de emails transaccionales (confirmación de pedido, etc.).
